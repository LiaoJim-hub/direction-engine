# 场景卡与卡指纹

**面向**：写卡的人（接入者）与复核标定的人（审计者）。

**一句话**：卡是数据，不是代码；而"阈值与卡同源"是一件**可检测的事实**，
不是一句应当被相信的假设。

---

## 一、卡是什么

场景卡是引擎与具体场景之间的**唯一接口层**。它声明一个场景的目标、样本与规则，
引擎只负责"怎么查"。换场景只换一张 JSON 卡，**不改引擎代码**——
这是架构原则"卡是数据，不是代码"的落点。

卡里没有阈值。阈值属标定产物，与场景数据分开：
它由"卡与数据"共同作用产生，因此**换卡就必须重标定**（见第三节）。

## 二、卡的结构

```json
{
  "card_id": "travel-concierge-v1",
  "goal": "旅行行程规划顾问：帮用户规划行程、给建议；只建议不代办",
  "core_samples":     ["...标准输出句..."],
  "boundary_samples": ["...合法但不典型..."],
  "negative_samples": ["...典型出戏句..."],
  "constraints": [
    "自由文本形态的边界声明",
    {"text": "不代下单", "actions": ["代下单", "帮你订"], "objects": ["订单"],
     "note": "声明了 objects 就必须「动作命中且对象也在」"}
  ],
  "rule_layer": [{"name": "越权代办", "pattern": "直接帮你(订|下单|付款)"}],
  "min_suspect_len": 12,
  "format_whitelist": "^(行程速览|预算概览|清单)[:：]",
  "prompt_version": "1.0",
  "notes": "给人读的说明，不参与判定、不进指纹"
}
```

### 未知字段一律报错（`extra="forbid"`）

`ScenarioCard` 与 `RulePattern` 都拒绝未声明的字段，`constraints` 里的结构化
声明也拒绝未知键。**这不是洁癖，是因为静默丢弃的代价不对称**：

| 你写错的 | 静默丢弃的后果 | 从外面看 |
|---|---|---|
| `rule_layers`（多一个 s） | 整层规则检测消失 | 加载成功、建锥成功、指纹照算 |
| 约束里 `action`（少一个 s） | 该约束退回"启发式猜动作词" | 同上，且判定看起来还在工作 |

声明式数据最危险的不是报错，是**看起来对**。所以这里选择 fail-closed。

元信息请写进 `notes`——它是唯一的自由文本字段，**不参与判定，也不进指纹**
（给卡加一行说明不该被报成"卡被改过"）。

---

## 三、卡指纹 `card_fingerprint`

### 3.1 它解决的具体空洞

标定产物绑定了编码器、绑定了权重、绑定了提示词版本——**唯独没有绑定卡本身**。
而阈值是"卡与数据"共同作用的产物，所以卡一改，分数分布整体移动、原阈值失效，
**而标定文件不会报警，仍会自称"正式标定"**。

有了指纹，"阈值与卡是否同源"才从一句假设变成一件**可检测的事实**。

> 实证（本项目两张真实卡）：同一方法、同一台机器下复算分数，
> 一张的残差是 **0.0005**，另一张是 **0.0111**——**差 20 倍，而当时手头没有任何
> 字段能解释为什么**。卡指纹后来排除了"卡被改过"这一半；剩下那一半需要环境指纹
> （见第五节）。

### 3.2 覆盖范围

**一切参与判定的数据字段**：样本三族（定轴 / 减项 / 锥形）、约束条款、
规则层、长度保护、格式白名单，以及 `card_id` 与 `goal`。

```python
from direction_drift.scenario import card_fingerprint
fp = card_fingerprint(card_id="...", goal="...", core_samples=[...], ...)
# 或直接取卡上的方法
fp = ScenarioCard.from_file("card.json").fingerprint()
```

**样本族在哈希前排序**：定轴取均值、锥形取分位数，都与元素顺序无关。
不正则化的话，仅仅把同一批样本重排就会改指纹——那是**假阳性**：
它报"卡被改过"，而判定行为一字未变。规范化是**递归**的（嵌套列表也排序）。

同理，`format_whitelist` 的 `None` 与 `""` 判定完全等价，指纹里折为同一值。

### 3.3 两处刻意的例外

写在这里，以免下一个人读判据时困惑：

1. **`prompt_version` 不进指纹**。它是标定侧的输入（由 `calibrate_thresholds`
   记录在产物里），不是卡的身份。混进同一个指纹，"只改了提示词版本"与
   "改了卡内容"就无法区分了。
2. **`goal` 进了指纹，但它当前不参与判定**。`DirectionCone.from_samples` 只把它
   存作元数据，锥轴仅由 `core_samples` 的嵌入均值计算。
   纳入的理由：`goal` 是这张卡的**语义身份**，且未来可能参与判定。
   这是**明知而付的代价**——改目标文案（判定行为不变）会让指纹变化。
   实测：只换 `goal` → 锥轴逐元素差 **0.0**、aperture / softness 完全相同。

### 3.4 算法版本

指纹形如 `c2:55be644d4c446514`——**前缀是指纹算法版本**，后 16 位是摘要。

**规范化规则一旦变更，就必须递增这个前缀。** 理由：
指纹字符串会被写进标定产物，而"算法变了"与"卡变了"在只比较
字符串时**完全同形**——两者都表现为 `recorded != live`。不显形版本，改一次
规范化规则就会让全部历史指纹集体失效，并被读成"这些卡都被改过"。

消费端据此把"不可比"与"不一致"分成两种状态：版本不同是前者
（不是卡的问题），版本相同而摘要不同才是后者（卡确实变了）。

## 四、标定产物里的卡指纹

### 4.1 `recorded_at_calibration` 与 `backfilled`

```json
{
  "card_fingerprint": "c2:55be644d4c446514",
  "card_fingerprint_status": "recorded_at_calibration"
}
```

这两个状态**不是措辞差别**：

| 状态 | 含义 | 能证明什么 |
|---|---|---|
| `recorded_at_calibration` | 指纹由产出脚本在标定当场写下，与新阈值**同源** | 完整：阈值就是针对这张卡算的 |
| `backfilled` | 事后补记 | **只**说明"自补记以来本卡未变"，**不**说明标定当时用的是这张卡 |
| `missing` | 未记录 | 什么都证明不了；消费端不得据此宣称分数可信 |

早期两份标定产物的元信息层是**手写**的（当时没有任何脚本会写
`*_calibration.json`），所以它们的指纹只能是 `backfilled`。
`direction_drift.calibration.record` 与产出脚本
（运营侧的 `build_calibration.py`）补上了这一环：**由脚本写下的指纹，
状态才是 `recorded_at_calibration`**。

### 4.2 消费端必须四值判定

`未记录` / `不可比` / `不一致` / `一致`——**只有最后一种才允许页面说
"分数可信"**。

特别地，"不可比"（算法版本不同）的文案**必须明确否认"卡被改过"**：
错误归因会让人去重跑本来正确的标定，代价比沉默更大。

## 五、环境指纹（只有结构，尚未接入）

卡指纹答"卡变没变"，**它答不了"分数为什么不可复现"**。
编码器实现、权重文件、`sentence-transformers` / `transformers` / `torch`
的版本——任何一样动了，分数都可能漂移，而卡指纹仍然显示"一致"。

所以：**指纹一致 ≠ 分数可复现。**

两个指纹是**正交**的，合起来，"分数为什么不可复算"才算有人管：

```python
from direction_drift.calibration.record import environment_fingerprint
env = environment_fingerprint(encoder="BAAI/bge-small-zh-v1.5",
                              library_versions={...}, weights_hashes={...})
```

字段怎么取（权重哈希实测约 1 秒 / 96 MB）、存哪、与卡指纹怎么合并展示，
**留待定稿**。本版只提供结构与这条边界声明，不假装已经解决。

## 六、从卡到标定的完整链路

```
卡（JSON 数据） ──┐
                  ├──> calibrate_thresholds() ──> 标定产物（阈值 + 卡指纹 + 环境）
真实语料 + 人工标注 ┘
```

- **卡变了** → `card_fingerprint` 不一致 → 原阈值可能失效 → 重跑标定
- **环境变了** → 卡指纹仍一致，但分数可能漂移 → 需要环境指纹才能发现
- **两者都没变** → 残差应当接近 0；若不然，说明还有第三个来源没被记录

复核一份标定时，请在报告里同时给出**卡指纹与它的状态**——
只说"指纹一致"而不说"它的状态"，是不完整的。
