# 「意向性生成模型」提案评估

> **本文性质**：维护者对一份外部提案的**评审记录**，不是路线图承诺。
> 记录日期 2026-09-29，基准版本 v2.3.2。
> 提案内容：主张把引擎从「漂移检测器」升级为「意向性结构生成模型」，分四步走
> （预测误差检测 / 视域分布 / 滞留—前摄连续流 / 约束＝充实—落空判据）。
>
> **一句话结论**：诊断三处有真东西，处方一处撞宪法，排序依据不成立。
> 采纳其中不冲突的部分作为可选实验方向，但排在「最后一公里」之后。

## 一、它说对了什么

1. **引擎当前做的是「朝向的静态快照的偏离测量」**——这是准确的自我描述。
   输出只在「某一次输出」上给判定，不产出任何关于「下一次」的信息。
2. **「别上深度学习」与项目气质一致**，且这不是偏好而是结构约束：
   `DemoEncoder` 存在的理由就是 CI 免 torch，`tests/test_coexistence.py` 有
   零依赖架构守卫。低阶时序模型（指数平滑 / 增量统计）在量级上是合适的。
3. **「前摄完全没有」——属实**。全仓检索 `protention|predict|forecast|anticipat`
   零命中（唯一命中是负面样本里那句「预测一下明天股市大盘走势」）。
4. **第四步（约束 ↔ 充实/落空）作为解释有价值**，且几乎零成本（见第五节）。

## 二、事实核对：三处需要修正

### 2.1 「完全没有时间结构」——不准确，准确说法是「零阶预测器」

引擎已有一批时间性成员，只是它们不叫这个名字：

| 现有成员 | 时间含义 |
|---|---|
| `history`（deque, maxlen=50） | **持留**：过去窗口内的全部轨迹 |
| `mean_score` | 窗口均值 = **零阶预测器**（隐含假说「下一步 ≈ 历史平均」） |
| `slope`（对 `means` 做一阶拟合） | **趋势估计量**，已经是外推的雏形 |
| `low_ratio` | 窗口内失分占比（频率型统计） |
| `_cusum_s` | **偏离的持续累积**——与提案第一步要的「预测误差的持续累积」同族 |
| `archive` | `reset()` 时归档，审计链不断 |
| `history_size` → `confidence` | 判定强度随样本量分层 |

准确的说法是：**引擎已经有误差累积器（CUSUM）与趋势估计量（slope），
缺的是「预测器」这一环——它现在拿常数模型（历史质心）当预测器。**

这个区别决定了工程量：第一步不是「从无到有的范式切换」，而是
**把零阶预测器换成低阶预测器**（并保留既有累积器）。也正因为如此，
提案那句「缺的不是算法复杂度，而是一次范式切换」**恰好说反了**——
它要的每一步在工程上都是「换成另一种统计量」，难度落在
「能否被真实数据检验」，不落在算法复杂度。

### 2.2 「返回协议 = 滞留」——命名错位，属不同层次

`ReturnProtocol` 的状态机（running / observing / paused / returning）与
`DirectionCone.freeze()` 属于**姿态层**（Blickwendung）：主动停、主动看、
主动决定是否返回。而胡塞尔的滞留（Retention）是被动的、非主题化的
「刚过去者仍被持留」。两者不在同一层——**把主动决定当作被动持留，
会让后续设计错层**。更贴的对应是：

| 现象学层次 | 引擎中现有对应 |
|---|---|
| 原印象（现在） | 最新一条 `score`（但无「当下的厚度」） |
| 滞留（刚过去） | `history` 窗口 + `means` + `archive` |
| 前摄（即将来） | **无**（这一条提案说对了） |
| 反思/姿态层 | `ReturnProtocol` + `cone.freeze/unfreeze` |

「返回协议属姿态层而非时间意识层」这个区分本身值得写进
`docs/philosophy.md`——它是本仓第一次把这两层显式分开。

### 2.3 「方向锥是硬边界」——半对，已有软边界带

`DirectionCone.contains()` 返回三档 `core / boundary / outside`，
边界带由 `aperture ± softness` 给出（`aperture` = 核心样本夹角的 95 分位，
`softness` = 边界样本夹角的标准差）。所以**不是硬边界**。

但**确实不是概率分布**：分位数描述的是「哪些被算作在轨」，
似然描述的是「有多可能」。提案要的改造应准确表述为
**从分位数边界 → 似然/密度**，而不是「从硬边界 → 分布」。

## 三、一条硬冲突：不能「用误差修正」

提案第一步原文：*「让引擎预测下一步方向，然后量实际 vs 预测的误差……
主动预测输入、用误差修正」*，并称之为「信念更新 = 预测误差驱动」。

**「用误差修正」这一步越界，不能采纳。** 三处依据：

1. `CONSTITUTION.md` 一.4「不把引擎当根」：*无自动改写、无自动恢复、
   无绕过人工的执行路径。任何「顺手帮用户自动修一下」的功能都与本宪法冲突。*
2. `CONSTITUTION.md` 二：新能力*不减少人的决定点，只增加人的信息量*。
   让预测误差参与更新 = 引擎替人做了「当前朝向该不该改」的决定。
3. 代码层已有对应的刻意红线：`DirectionCone.rebuild_from_samples()` 的
   docstring 写着「**不存在对单条输出的 EMA 更新**」——这是设计，不是漏做。

**这条红线有硬经验理由，而提案没有看到：漂移吸收（drift absorption）。**
若模型随输入更新，一个缓慢偏出的生成器会把模型一起拖着走——每一步的
「偏离」都被吸收进新基线，漂移不再可检测。**一个会跟着跑的检测器，
等于没有检测器。** 这正是「未标定不判定」与「禁止 EMA 更新」存在的经验根据。

**可采纳的形式**：`预测 → 输出预期区间与实际落点 → 显形误差`。
预测结果**不参与**任何更新（不改锥、不改阈值、不改 history 语义），
判定链一个字不动。这样它仍在宪法之内：引擎多给一条信息，人自己决定怎么用。

## 四、哲学层三处校正

本项目对引用一向执行诚实边界纪律，故对提案的理论表述也须同样处理：

1. **「意向性首先是时间性的」是海德格尔化的读法**（《存在与时间》），
   不是胡塞尔的原文立场。在胡塞尔那里，内时间意识是意向性的
   **发生条件（基础层次）**，意向性本身还含 Noema/Noesis 相关、视域、
   本质直观等结构。表述应改为「**时间意识是意向性的发生条件**」。
2. **视域 ≠ 概率分布。** 视域的关键规定性是「未主题化但可被唤醒」
   （Habitualität / Weckbarkeit）。而概率分布要求先把可能项枚举、主题化，
   才能赋概率——**分布化恰好丢掉了「未主题化」这一规定性**。
   若工程上真要保「可唤醒而未主题化」，对应物更接近
   「**可达但未被采样的邻域**」（低密度可达区），而非显式似然参数。
   这不否定提案的方向，但否定它的命名——**命名错了，设计目标会跟着错**。
3. **充实/落空（Erfüllung / Enttäuschung）≠ 约束检查器。**
   充实/落空的主体是**意向行为自身**的预期被满足或被否定；
   约束是**外部给定的规范**。二者可以类比（用于讲解），不能等价（用于定义）。

## 五、四步逐条裁定

| 步 | 提案主张 | 裁定 | 处置 |
|---|---|---|---|
| 一 | 漂移检测 → 预测误差检测 | **部分已存在**（CUSUM 即误差累积）；「修正」部分越界 | 可做，但须改写为「预测—显形」；见第三、七节 |
| 二 | 锥 → 视域/可能性分布 | 技术可行（核密度 / 马氏距离），但会丢「未主题化」；价值待验证 | **延后** |
| 三 | 返回协议 → 滞留—前摄连续流 | 滞留已由 history/means 承载；缺的是前摄**内容**（即第一步） | **降级为命名层** + 附属于第一步 |
| 四 | 约束 = 充实/落空判据 | 类比可用、等价不行 | **采纳为文档层类比**，须标注「类比非等价」 |

## 六、与提案不同的排序（及理由）

提案把第一步排最先，理由是「今天就做得动」。**这个依据不成立**：
做得动不等于该先做。

**两个反驳**

1. **它需要真实文本流才能被检验。** 文本方向分上的低阶外推噪声极大
   （分数同时受文本长度、编码器噪声、样本分布影响）。没有连续的真实流，
   只能在自己造的合成序列上「看起来有效」——正好撞 `CONSTITUTION.md` 三
   （标定诚实性：合成数据不得用作性能估计）。
2. **项目当前的瓶颈不在理论深度。** 现状是：零外部接入方；私有运营目录
   两张卡未落成 `ScenarioCard`（卡要素仍是脚本常量）；HTTP API 不吃卡；
   建卡指引散在四份文件；托管仓 11 端点仍 501。先做 protention，
   是在**最没人走的那条路上再铺一层**。

**建议排序**

0. 清账：删重复 `scenario.py`、收口建卡指引、修 API 与 README 的能力声明；
1. 第一个真实接入方（自有业务线即可）——它同时是第 3 步的检验材料；
2. 托管真实实现，或明确宣布暂不做；
3. protention 实验模块（显形式、低阶预测器）；
4. 视域**分布**化（若届时仍被判定有价值）。

**一个例外条件**：若本项目的目的是**把《内时间意识现象学》变成可运行代码**
（研究目的），而不是做一个被采用的工具，那么把第 3 步提到最先是对的——
研究目的下理论完整性优先于用户采纳。**先定目的，再定排序。**

### 6.1 排序已定（2026-09-29）：例外不成立，protention 垫底

目的问题当日得到回答：**本项目是工具，不是研究。** 三处依据，指向同一结论：

1. **定位自述**（[`philosophy.md`](philosophy.md) 第一节）：本引擎是「方向性基础
   设施」的**一层**——提供方向的度量与显形能力，**不提供方向本身**（方向由接入方
   的样本与场景卡给出）。这句话的语法本身就是基础设施的语法：服务于别人，不自足。
2. **项目给自己的价值排序**（同上第三节）：最有价值的是**显形机制**，最不重要的
   是分数——按"对使用者的用处"排，而不是按"理论完备性"排。
3. **治理与商业设计**（[`CONSTITUTION.md`](../CONSTITUTION.md) 一.3）：托管服务
   按接入系统数定价、全量档案随时可导出、离开成本必须为零。**定价口径的存在本身
   就预设了要有人来用。**

故第六节开头的排序维持不变：**protention 排最后（第 4 位）**，在清账、第一个真实
接入方、托管真实实现之后。**它不是被宪法否决的**——显形式（只读 history、不参与
任何更新）在第三节已论证为合宪；它是被**优先级**否决的：项目当前的瓶颈不在理论
深度，在无人真实使用。

例外条件本身保留在上面，作为推理链的一部分：**它记录的是"排序取决于目的"这个
判据，而不是一个待办。** 若将来项目性质改变（例如以论文为主要产出），应重新走
一遍这一步，而不是在这里就地改排序。

## 七、附录：最小设计草案（未实现，备将来）

```python
class ProtentionTracker:
    """前摄（显形式）：给出下一步朝向的预期区间与实际落点，只显形不修正。

    纪律：
    - 只读 history（不写回）；预测结果不参与任何更新；
    - 未标定或窗口不足 → pending_verification（同 provenance 的 W_PENDING）；
    - 输出不含任何 modify/act 类字段。
    """

    def __init__(self, window: int = 5, method: str = "ses", alpha: float = 0.3): ...

    def observe(self, score: float, ts: str = "") -> dict:
        # {"expected": float, "band": [lo, hi], "actual": float,
        #  "error": float, "streak": int, "cusum_alarm": bool,
        #  "pending_verification": bool, "note": str}
        ...

    def to_dict(self) -> dict: ...

    @classmethod
    def from_dict(cls, data) -> "ProtentionTracker": ...
```

三条硬约束（须写成测试守卫，照 `tests/test_coexistence.py` 的写法）：

1. 不 import 检测链的判定结果去改判定——只读 `history`；
2. 结果字典不含 `modify / act / update / apply` 类键（断言键集）；
3. 未标定 → `pending_verification=True`，且不得产出 `drift_level` 级结论。

预测器候选（**不用深度模型**）：单指数平滑（SES）→ Holt 线性趋势 →
卡尔曼（状态 = [水平, 斜率]，观测 = score）。三档递进，
第一档就能验证「低阶外推是否比零阶更有信息」。

## 八、把这个提案本身当一次检测

用引擎自己的判据看这份提案：

- **方向对齐度不低**——它抓住了「事前 vs 事后」「主动 vs 被动」这条真边界，
  并且明确反对上深度学习，与本项目气质一致；
- **但约束层有一条明确越界**——「用误差修正」撞 `CONSTITUTION.md` 一.4。

**方向不错，越了边界**——这正是引擎在真实语料上最常抓到的那一类漂移。
提案结尾那句「连『全面检查』也是显化」说得对，只是这一次被显化的是它自己的越界。
