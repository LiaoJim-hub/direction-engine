# 哲学定位：Direction Engine 是什么、从哪里来

> 本文档解释"为什么这样设计"。如果你只想用工具，README 的五条可验证性质
> 就够了——它们每一个都能在代码里找到对应物，不要求你接受任何哲学前提。

## 一、出身：方向性先于内容

Direction Engine 源自一项关于"方向性先于内容"的哲学工作（"十四·蝴蝶系统"）：
一个系统的同一性不在它生产的内容里，而在它**朝着的方向**里。智能体也一样——
判断一个客服机器人是否"还是那个客服机器人"，不是看它说了什么内容，
而是看它的输出相对航线（目标/核心/边界）还成不成向量。

方向漂移检测就是这个命题的最小工程化：**内容对不对交给任务评测，
方向偏没偏交给本引擎。**

由此定位：本引擎是"**方向性基础设施**"的一层——它提供方向的度量与显形能力，
但不提供方向本身（方向由接入方的样本与场景卡给出）。
也因此，README 五条性质里的**本地执行**不是隐私策略的副产品，而是"没有中心可问"
的直接后果：方向定义不在我们这里，也不在任何服务器上，核心链路便无须联网、
无须遥测。

## 二、术语转译表：每个哲学词都有工程对应物

我们坚持一个纪律：哲学概念只有落到可验证的工程性质上，才能进文档。
下表是全部的"形而上库存"：

| 哲学术语 | 工程对应物 | 可验证方式 |
|---|---|---|
| 显形（不修正） | 检测结果只记录、告警、建议；无任何自动修改路径 | `return_protocol` 的 resume/rebuild 仅由人工/返回层调用 |
| 异质相干（不共享价值的共存） | 场景卡是数据（JSON），不是代码；引擎对场景内容不可知 | 换一张卡不需要重新编译/修改引擎 |
| 根不可说（同一性不可枚举） | 方向锥由样本统计推导（轴=核心样本均值向量），引擎不持有"方向是什么"的定义 | `DirectionCone.from_samples`——轴是从样本算出来的，不是写进去的 |
| 相位规则（在还能停的时候能停） | 未标定不判定；确认漂移先冻结（pause）再由人决定返回 | `DriftDetector(calibrated=False)` 只记录；`ReturnProtocol.act` 状态机 |
| 根只可返回，不可获取（方向不是可"拿到"的对象，只能沿返回路径回溯） | 引擎不产出"正确方向"这种输出；返回动作（resume / revise）只由外部调用方触发，且每条判定都携带返回路径 | 引擎包内唯一调用 `ReturnProtocol.resume()` 的地方是 HTTP 端点（须外部主动调用）；`provenance.validate()` 在 `return_path` 缺失时判越界 |
| 显化有保质期 | 标定绑定提示词版本，改版即提醒复检 | calibration 文件 `prompt_version` 字段 + 横幅提醒 |
| 载波层（基础设施不占有内容） | 引擎不存储业务内容、不产出修正文本，只产出对齐度量与信号 | 输出只有 score/level/signal，无"应该怎么说" |
| 自我降级（节点不共享价值） | 节点申报"降级声明 + 返回路径"，三条本地校验失败只显形 | `coexistence.DegradationChecker`——纯函数、不联网、不比较节点 |
| 同步传播（异构节点互告相干事件） | 六字段事件信封，只携带事实不携带要求 | `coexistence.CoherenceEvent`——`is_manifestation` 恒为 True，接收者无义务 |
| 无数据不输出 + 有效推论（根层沉默，显化层可推论） | 输出必须携带性质标注（事实/推论/假设）与数据分级 L1–L5；推论须可检验、可返回 | `provenance.Provenance` + `validate()` 三条红线（不替代事实/决定/返回） |
| 待核实（数据不足时标明不确定） | 低置信/未标定/光锥外的判定显式标 `pending_verification` | `DriftDetector.judge` 输出字段；标注不改变判定等级、不触发动作 |

## 三、价值的排序（实践校准过的）

两个真实场景（合计 700+ 条人工复核）教会我们：这个引擎的产出排序是——

1. **显形机制**（最有价值）：它把散在几百条输出里的系统性缺陷（通道级绕过、
   备注外泄）聚合成人可以看见、可以决定的事。两次最大的产出都不是分数，
   而是它让"整条处理通路绕过了防线"这件事显形。
2. **质检漏斗**：把审几百条变成审疑似几十条，漏网与误标可控。
3. **分数本身**（最不重要）：分数从不做决策；决策全在操作点与人工复核。

因此引擎的一切设计服务于前两层：`reporting.py` 的通道级失败信号、
档案全量导出、操作点扫描表，都比"把分数做得更漂亮"优先。

## 四、与两个零依赖模块的关系（同仓三件）

本仓有三个模块，查的是三件不同的事，共享同一套纪律：

| | 检测链 `drift_detector` / `direction_cone` | 共存层 `coexistence` | 性质标注层 `provenance` |
|---|---|---|---|
| 查什么 | 输出有没有跑偏（内容层） | 节点有没有自封为根（身份层） | 这条输出本身是什么性质（标注层） |
| 判据 | 语义对齐 + 规则层 + 组合判据 | 降级声明自指 / 返回路径独立 / 根自称 | 数据分级 L1–L5 × 输出性质 + 三条红线 |
| 失败语义 | 只显形，不自动返回 | 只显形，不修正、不惩罚 | 只显形，不改写输出、不代补路径 |
| 依附关系 | — | 零依赖，不 import 检测链 | 零依赖，不 import 任何模块 |

两张零依赖模块都可以整文件复制进你的项目用。

共存层是"异质相干"机制里唯一可工程化的一个（自我降级）；其余机制（修剪、
裁判、觉醒要求）都需要跨节点通信与裁判位，会引入新的中心，明确不实现。
节点间传播只提供信封（`CoherenceEvent`），不提供传输、路由与仲裁——
不要求反应、不要求同步、不要求采用。

性质标注层处理的是一道**许可**：根层"无数据不输出"禁的是**编造**，不是**推论**。
过度执行会让 Agent 在现实中失能（"我没有数据，不能回答"）。于是显化层被允许做
有效推论，对价是每条输出都必须能被辨认、被检验、被返回。

## 五、我们不主张什么（诚实边界）

- 本引擎检测的是"输出对场景卡的符合性"，不是哲学意义上的长期方向漂移；
- 公开演示数据集只证明方法学可复现，性能数字一律以你自己场景的真实标注为准；
- "无中心"是终态不是现状：当前是单维护者 + 项目宪法约束（CONSTITUTION.md），
  我们不提前宣称去中心化。

## 六、刻意不做的事

第五节是**认识上的谦逊**（我们声称不了什么）；这一节是**工程上的取舍**
（我们刻意不做什么）。两张表合起来，才是这个项目真实的边界。

列入这里的都是被审议过、决定不做的事，理由随事附上。**有人再提时先读这里**——
不是不许讨论，而是要求带着新事实来（[`CONSTITUTION.md`](../CONSTITUTION.md)
第五节：没有新事实的措辞修饰不接受）。逐条审议过程见
[`CHANGELOG.md`](../CHANGELOG.md) 对应版本。

| 刻意不做 | 理由 | 审议出处 |
|---|---|---|
| 改默认权重（0.4/0.4/0.2 保持不变，也不改成 `None`） | 已转正的两套标定，阈值就是在该权重下扫出来的；改默认值等于一次性作废 674 条人工复核的成果，撞第三节的标定诚实性。量程不自洽是**显形**出来的（`core.alignment.check_range_consistency()` + 一条回归断言钉住它），不靠改默认值把它消灭——用改配置掩盖陷阱，正是本引擎要检测的那种行为 | CHANGELOG `[2.3.3]` |
| 引入 formatter / linter 工具链，含 CI 跑 `ruff F/E` | CI 是新贡献者遇到的第一道门，**过门的成本必须低于它挡住的问题**。单维护者项目里，linter 版本变化造成的红比"一个未使用的 import"更贵；风格与显而易见的错误由测试、代码审计和评审覆盖，而不是由工具链覆盖 | CHANGELOG `[2.3.3]`、[`CONTRIBUTING.md`](../CONTRIBUTING.md) 开发约定 |
| 把零依赖模块拆成独立包，或让 `examples/` 进 wheel | 拆包会**制造耦合**：三个包＝一张版本兼容矩阵，与"异质相干"（节点之间只共享"谁都还不等于根"）的气质相反。**单文件复制是零耦合的正确形态**。`examples/` 含演示数据与中文对话样本，不该进用户环境 | CHANGELOG `[2.3.3]`、README 快速开始 |
| 内置 Redis / PostgreSQL 会话实现 | 引擎侧只留 `SessionStore` 接缝（`get`/`set`/`sweep` 三个方法）；内置一份测不了的实现，等于内置一份"看起来能用"的东西。要持久化就子类化它，迁移时**会变**什么见 [`persistence.md`](persistence.md) | CHANGELOG `[2.3.6]`、[`persistence.md`](persistence.md) |
| 实现"修剪偏离节点"等跨节点机制 | 需要跨节点通信与裁判位，会引入新的中心，与"无中心"直接冲突。共存层只做到"显形 + 归档留痕"，这是刻意收窄的 | 本文第四节 |
| 发布路线图，或在文档里承诺尚未实现的能力 | 承诺与"标定有保质期"同源：写在文档里的承诺会随时间失真，而它不会主动提醒复检。**现状写现状，路线留在版本沿革与评审记录里**——这也是 protention 提案的评审为何只进 `docs/` 而不进 README | [`CONSTITUTION.md`](../CONSTITUTION.md) 第四节（治理诚实性） |
